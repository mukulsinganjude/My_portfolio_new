LEARNING NOTES

THREE-TIER CONCEPT

Separate responsibilities. Connect securely.

A common web architecture separates incoming traffic, application processing, and persistent data so each tier can be managed with clear boundaries.

  • Web tier: Nginx receives and routes requests.
  • Application tier: Tomcat runs the application layer.
  • Data tier: a relational database stores application data.

AWS 3-Tier Architecture

02
Infrastructure learning project

A learning design for a three-tier request path: Nginx on a web-tier EC2 instance, Tomcat on an application-tier EC2 instance, and a relational database behind private network boundaries.

AWS EC2VPCNginxTomcatRelational DB

PROJECT CASE STUDY · INFRASTRUCTURE LEARNING

Goal: explore separation between the web, application, and data layers with explicit network boundaries.

Planned request flow

Browser → public web subnet (EC2/Nginx) → private application subnet (EC2/Tomcat) → private data subnet (relational database).

Components in the design

Amazon VPC and subnet boundaries, EC2 compute for the web and application tiers, Nginx, Tomcat, and a relational database layer.

Intended trust boundaries

Allow web requests to reach the web tier, permit only required web-to-app and app-to-database paths, and avoid direct public access to the data tier. Exact rules and ports require confirmation.

Verification before deployment claims

Record actual subnet CIDRs, security-group rules, instance details, database type, health checks, and runbook steps only after they are verified.

This diagram describes an intended learning architecture only. No deployed VPC, EC2 instances, Nginx/Tomcat services, database, or live endpoint are asserted here.
